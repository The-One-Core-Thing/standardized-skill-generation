# Phase 1: 问题分析

## 输入
- Phase 0 输出的结构化变更列表

## 前置条件
- severity-rules.yaml 已加载

## 执行步骤
1. 逐文件扫描，对照 severity-rules.yaml 中的规则
2. 识别安全漏洞（SQL 注入、XSS、敏感信息泄露）
3. 识别性能问题（N+1 查询、内存泄漏、不必要的循环）
4. 识别代码质量问题（错误处理缺失、异常吞没、资源未释放）
5. 按严重性分级：Critical / Major / Minor / Info

## 输出
- 问题列表（含文件位置、问题描述、严重性、修复建议）

## 完成条件
- 每个变更文件都已扫描
- 所有问题已分级
- Critical 级问题必须附带修复建议
