# 调研笔记 03：审查方式对比

> Phase 1 产物 · 内容研究阶段
> 目的：明确「AI Skill 辅助审查」在整个审查生态中的定位，避免 Skill 越位或缺位。

---

## 1. 三类审查方式概览

| 方式 | 代表 | 强项 | 弱项 |
|------|------|------|------|
| 人工同伴审查 | GitHub PR Review、Gerrit | 业务理解、设计判断、上下文敏感 | 慢、主观、容易 nit-pick |
| 自动化静态规则 | ESLint、golangci-lint、SonarQube | 快、规则一致、覆盖广 | 噪音多、无业务理解 |
| AI 辅助审查 | 本 Skill、CodeRabbit、GitHub Copilot Review | 快 + 一定业务理解 | 易幻觉、知识截止、不可执行验证 |

---

## 2. 详细对比

### 2.1 人工同伴审查

**优势：**
- 能把代码与业务/团队约定挂钩
- 能判断"做不做"的设计层问题
- 提供成长反馈（mentorship）

**劣势：**
- 平均响应时间 > 4 小时（SmartBear 数据）
- 不同审查者标准差异大
- 容易陷入风格争论
- 受疲劳影响明显（>60min 漏检率飙升）

**最适合**：架构变更、新模块、跨团队接口

---

### 2.2 自动化静态规则（Linter / SAST）

**优势：**
- 秒级响应、CI 内置
- 规则确定，不会"忘记"检查
- 覆盖语言/框架已知模式

**劣势：**
- 假阳性高，习惯性 `// nolint`
- 不理解业务语义
- 跨文件分析能力弱（除非专业 SAST）

**典型工具：**
- 通用：SonarQube、Semgrep
- Go：golangci-lint（含 staticcheck、gosec、errcheck）
- Python：ruff、bandit、mypy
- JS/TS：eslint、@typescript-eslint
- Java：SpotBugs、PMD、Checkstyle

**最适合**：风格、明确反模式、已知漏洞模式

---

### 2.3 AI 辅助审查（本 Skill 类）

**优势：**
- 能理解自然语言 context
- 能跨语言/跨框架做通用判断
- 能用人话解释"为什么是问题"
- 比人工快、比 linter 灵活

**劣势：**
- 幻觉风险：可能"自信地编造" API
- 知识截止：新框架/新漏洞未必覆盖
- 无法执行：不能跑测试验证
- 容量限制：超长代码必须分批

**适用边界（本 Skill 立场）：**
- ✅ 适合：单文件/单 PR 的多维度初筛、对人工审查的辅助
- ❌ 不适合：替代专业安全审计、替代 CI 静态检查、替代单元测试

---

## 3. 三者协同模型（推荐）

```
        提交 PR
            │
            ▼
    ┌───────────────────┐
    │  CI 静态规则      │  ← 自动 / 强制 / 风格 + 已知反模式
    └─────────┬─────────┘
              │ 通过
              ▼
    ┌───────────────────┐
    │  AI Skill 初筛    │  ← 本 Skill / 多维度 / 给 Top 问题
    └─────────┬─────────┘
              │ 输出报告
              ▼
    ┌───────────────────┐
    │  人工同伴审查     │  ← 设计 + 业务 + 最终决策
    └───────────────────┘
```

本 Skill 的角色：**夹在 linter 与人工之间的"第一双眼睛"**。Linter 已经过的，由它再过一遍，把模式上没问题但语义可疑的找出来；同时把噪音过滤掉，让人工只看真问题。

---

## 4. 与同类 AI 审查工具的差异化

调研对象：CodeRabbit、Greptile、PR-Agent、GitHub Copilot Review

| 特性 | 同类工具 | 本 Skill |
|------|---------|---------|
| 集成方式 | GitHub App / CI 集成 | IDE 内 Skill，按需触发 |
| 输出风格 | 逐行内联评论 | 一次性结构化报告 |
| 严重度分级 | 部分有 / 部分没有 | 强制 4 级 |
| 风格问题 | 多数会提 | 默认跳过 |
| 不确定时 | 多数直接断言 | 强制提问句 |
| 输出长度 | 经常过长 | 强制 ≤ 15 条 |

**本 Skill 的差异化定位**：克制型审查者 — 宁可少说，不要说错；宁可问问题，不要乱断言。

---

## 5. 决策记录

基于以上对比，本 Skill 在设计中做了以下取舍（详见 `decisions.md`）：

1. **不内置 linter 能力**：依赖用户先跑过 CI；本 Skill 只补 linter 抓不到的语义问题
2. **不输出 inline 评论**：因为 IDE 内 Skill 不一定挂载到 PR；改为结构化报告
3. **强制限制反馈数量**：避免 AI"宁多勿少"的倾向，反 nit-picking
4. **强制提问替代断言**：对冲幻觉风险
