# SKILL.md 质量检查清单

发布前逐项检查，全部通过方可视为合格。

---

## 1. 结构完整性

- [ ] 文件以 YAML frontmatter 开头（`---` 包裹）
- [ ] `name` 字段存在且为 kebab-case 格式
- [ ] `description` 清晰描述功能，且包含触发条件/触发词
- [ ] `version` 字段存在且符合语义化版本
- [ ] 正文有明确的使用边界（何时用 / 何时不用）
- [ ] 正文有核心指令或流程 section
- [ ] 正文有约束/限制 section

---

## 2. 内容质量

- [ ] 决策规则使用 `If [条件] → Then [行动]` 格式，非抽象描述
- [ ] 包含具体的负面约束（明确说明不该做什么）
- [ ] 流程有明确的输入条件
- [ ] 流程有明确的输出定义
- [ ] 流程有明确的完成/退出条件
- [ ] 不依赖平台特定语法（保持通用性）
- [ ] 无歧义表述（同一指令不会产生两种理解）

---

## 3. 三重验证（认知类 Skill 特有）

适用于：思维模型、分析框架、决策方法论等认知类 Skill。
操作类 Skill（如代码生成、文件操作）可跳过此节。

- [ ] **跨域重复**：核心模型/模式在 2+ 不相关领域中出现
  - 验证方法：列出至少 2 个不同领域的应用实例
- [ ] **生成能力**：能对未见过的新场景做出预测或建议
  - 验证方法：构造一个训练集外的场景，检查模型是否产出合理输出
- [ ] **排他性**：不是通用常识或已被广泛文档化的知识
  - 验证方法：确认核心洞察不能通过简单搜索获得

---

## 4. 可用性验证

- [ ] **风格识别**：100-200 字的样本输出能让人识别出 Skill 的独特风格
- [ ] **正向测试**：3-5 个测试问题能正确触发并得到符合预期的响应
- [ ] **边界测试**：超出适用范围的问题能被诚实拒绝或降级处理
- [ ] **幂等性**：相同输入多次执行，输出结构一致（内容可有合理变化）

---

## 5. 格式合规

- [ ] Markdown 渲染无语法错误
- [ ] 标题层级正确（`#` > `##` > `###`，不跳级）
- [ ] 代码块标注语言类型
- [ ] 表格对齐、列数一致
- [ ] 无孤立链接或失效引用

---

## 快速判定

| 级别 | 条件 | 结论 |
|------|------|------|
| ✅ 通过 | 第 1-2 节全部勾选 + 第 4 节至少 3 项通过 | 可发布 |
| ⚠️ 需改进 | 第 1 节全部勾选，但第 2 节有未通过项 | 修改后重检 |
| ❌ 不通过 | 第 1 节有未勾选项 | 结构不完整，需重写 |

---

## 使用方式

1. 完成 SKILL.md 编写后，逐项对照本清单
2. 未通过项标注原因并修复
3. 认知类 Skill 额外完成第 3 节验证
4. 全部通过后，在 commit message 中注明 `quality: passed`
